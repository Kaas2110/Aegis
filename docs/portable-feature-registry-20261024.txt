PROVENANCE AND INVALIDATION

artifacts/2026-10-24.r1 contains the index, family document, target matrix, semantic
disposition ledger, provenance and bundle manifest. Their metadata is portable;
historical local evidence references are descriptive relative identifiers and are
never opened by the runtime loader. Raw observations, databases, archives, fitted
weights and credentials are absent. Legacy ordered-name bodies are not duplicated.
Original Russian family names/formulas are retained only as explicitly identified
quoted historical evidence; authoritative family descriptions are in English.

The bundle loader checks artifact byte lengths/hashes, registry structure, scope
policy, exact ledger coverage and cross-artifact bindings. The index includes
ledger/provenance pins and the scope policy, so changing those inputs changes the
semantic registry hash used by downstream schemas. An optional expected hash
rejects a stale binding. These host-owned metadata checks are not a signature or
proof of provider truth. The immutable registry is cached per module lifetime;
install a changed bundle through a new reviewed version and restart its consumer.

The ledger distinguishes not generated, partially generated, exact alias,
unavailable input, learned-state pending, label-only and presentation-only. It
authorizes no exact aliases. A family containing a generated subset remains
incomplete. Old formulas with no exact executable migration have null new IDs,
formulas and versions. A directory evidence reference explicitly has no content
hash and cannot stand in for a formula pin. Source references are historical pins,
not an assertion that the referenced file still has those bytes after later work.

DECISIONS AND ALTERNATIVES

The occurrence ranges preserve all old alternatives without duplicating roughly
34 MB of names in every application checkout. Supplying a name corpus remains an
explicit audit operation, and its full ordered hash must match first. Blindly
concatenating C1/C2/ProfileBuilder/native vectors was rejected because identical
names and widths do not establish formula, unit, profile or availability equality.
Declaring all families implemented from one column was rejected. Unresolved rows
retain a precise next action instead of invented aliases or feature availability.
