# Подготовка Aegis к RuStore

Проверено 19 октября 2026 года. Это инструкция подготовки; публикация и соответствие модерации не подтверждены. Сначала завершаются модели и сквозная проверка приложения, затем независимая приёмка Astra.

## Что уже есть

- React Native / Expo Android и полноценный пользовательский веб-клиент используют общие API.
- Локальный r6 APK установлен на согласованный эмулятор без очистки данных. Проверены подпись v2, ZIP alignment 16 KiB, minSDK 24 / targetSDK 36, ABI arm64-v8a и x86_64. Это `com.aegis.dota.local`, версия 1.0.0 / code 1, с AndroidDebug-подписью и локальным API; магазинным релизом она не является. Веб и Android показывают только «Прогноз недоступен», когда расчёт невозможен; технические причины остаются во внутренней диагностике.
- Регистрация, экспорт и удаление аккаунта, управление согласием уже реализованы. Не создавать второй набор этих функций по старым TODO.
- API обслуживает локальный сайт и админку. Origin браузера проверяется по явному списку; старый Replit fallback реферальной ссылки удалён.

Свидетельства: `work/android-web-readiness-20261019/REPORT.txt`, `outputs/r6.build-info.json`, `work/sol-forecast-copy-20261019/ANDROID-INSTALL.json`, `work/sol-forecast-copy-20261019/ANDROID-UI-RESULT.json`, `work/sol-analytics-install-20261019/HTTP-SMOKE.json` в рабочей папке чата. Поле `installed: false` в build-info отражает момент сборки; более поздняя установка подтверждена отдельным receipt. Метрики исследовательских моделей и факт сборки не подтверждают готовность продукта.

## Проверка правил

Официальные правила RuStore охватывают приложение и карточку: работоспособность, достоверность описания, права на материалы, конфиденциальность и разрешения. Для обрабатываемых персональных данных нужна доступная русскоязычная политика с описанием обработки, удаления и контактом ответственного лица. При наличии аккаунта предусмотрено его удаление. Раздел об азартных играх запрещает нелицензированные операции с денежными выигрышами; из него не следует автоматическое одобрение аналитики с коэффициентами.

Источник: [Правила модерации RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps), разделы 2.11, 4, 5 и 6. Предусмотрена загрузка APK/AAB; конкретные ограничения файла и формы надо сверить перед отправкой: [Документация разработчика](https://www.rustore.ru/help/developers).

Экран 18+ не заменяет проверку содержания и анкеты. Описание должно точно раскрывать аналитические вероятности и сравнение коэффициентов. Не обещать выигрыш или неподтверждённую точность. Не скрывать фактическую функцию ради модерации. Aegis не должен представляться официальным приложением Valve или букмекера.

## Порядок подготовки

1. Завершить контракты карты, серии и тоталов, фазы и внутреннюю диагностику свежести. При невозможном прогнозе на экране — только «Прогноз недоступен». Существование файла модели не заменяет независимую приёмку.
2. Пройти API → модель → экран: полный драфт, live, конец карты, следующая карта, BO1/3/5; главная показывает серию, детали — карту. С БК — её реальные линии, без БК — модельная сетка. Проверить сохранение выбора БК и отсутствие вымышленных коэффициентов.
3. На эмуляторе проверить навигацию, сессию, фон/возврат, потерю сети и восстановление, настройки, уведомления, большой экспорт. Согласия за владельца не принимать, данные не очищать. Физический Android не обязателен для согласованной локальной проверки.
4. Выбрать внешний HTTPS адрес и размещение сервера. До этого подготовить конфигурацию, но loopback не подходит для чужих устройств. Хостинг, туннель и покупки автоматически не создавать.
5. Задать `EXPO_PUBLIC_API_URL` при сборке. Проверить API, cookie/origin/proxy и разрешённые адреса. Веб-клиент при том же origin использует общий API. Ключи провайдеров и БД остаются на сервере.
6. Подтвердить постоянный applicationId (в исходном `app.json` — `com.aegis.dota`), версию и code. Подготовить постоянный release signing key с безопасным хранением. Пароли и ключ не класть в git, контекст-пакет или клиентский bundle. Не использовать AndroidDebug certificate для внешнего выпуска.
7. Собрать APK; проверить manifest, package/version, сертификат, ABI, alignment, отсутствие локального API и секретов; сохранить source manifest и SHA256. Установка `.local` не доказывает обновляемость production package.
8. Подготовить карточку по реальным полям консоли: название, описания, категория/возрастная анкета, иконка, скриншоты, контакт разработчика, публичные URL политики/поддержки. Размеры, число файлов и сроки модерации не считать гарантированными по старому черновику.
9. Только после отдельной команды владельца загрузить/отправить на модерацию. Раскрыть фактическое поведение, предоставить рабочий сервер и инструкции доступа, если нужны.

## Внешние условия выпуска

- Выбранный HTTPS API / вариант размещения.
- Данные разработчика и контакт для публичной политики/поддержки.
- Консоль RuStore и решение об идентичности приложения/подписи.
- Разрешение на загрузку и публикацию конкретной проверяемой сборки/карточки.

Эти условия не мешают локальным моделям и подготовке. Создание аккаунтов и принятие соглашений не подразумевать из задачи разработки.

## Обновления и другие магазины

Хранить постоянную идентичность и историю сертификата, увеличивать versionCode, фиксировать источник и сборку. Каналы платежей/push отделены от общего API/ML. SDK подключать под утверждённый сценарий; локальные уведомления не равны серверному push.

Правила других магазинов проверяются отдельно. Общая кодовая база не гарантирует одинаковой допустимости функций, подписок, выплат и внешних ссылок. См. `store-release-plan.md`.
