   A late download does not make an old game recent. Current-map labels remain
   excluded. Historical team/player/hero statistics are valid live inputs.

   creates a context valid from t1 with the SAME t0 cutoff. Actual materialization
   time is not backdated. Retained replay is not an originally issued forecast.

   Whole-series main and selected-map detail retain distinct identities, trace
   references and result orientation. Prior-map actuals remain separate.

  180seconds is a separate absent-phase progression qualification lease. The
   inspected diagnostic reader does not secretly shorten retention to180seconds.
   Fresh HTTP receipt alone cannot renew stationary state. Terminal, identity,
   rewind and manual STOP barriers remain stronger than the retention allowance.

   Keeping the unknown-stationary branch is correct; inventing pause evidence
   would not be a valid completion. Source event-to-app delay remains unmeasured.

PRIORITIZED FINDINGS
Paths below are relative to APP/scripts/steam-live-collector/source-adapter.

F1 — HIGH: absent-phase progression uses the wrong elapsed-time anchor.
steamProgressionAdmission.mjs:75-89 compares a new game-clock delta with the
last HTTP receipt gap, which can be a repeat. Example:12:30 clock600;12:31clock660;
12:32:59 repeated660;12:33clock780.120game seconds over120real seconds is plausible,
but the code compares120 with1+30 and rejects the new packet. The corrected
steamEligibleState logic cannot help without an admitted progression proof.
Use a separate clock-bearing anchor; preserve receipt chronology, qualification
lease, maximum-clock barriers and repeat non-renewal. Cover initial qualification,
restart and actual pipeline composition, not only explicit phase5.

F2 — MEDIUM BEFORE ACTIVATION: current route eligibility can be stale after IO.
diagnosticFeatureReadApi.mjs:32-37 / diagnosticTargetRouting.mjs:61-102 capture a
decision time before awaited trace/schema reads. A request begun at12:34:59 can
finish after12:35 expiry and still claim current eligibility at the old time.
Recheck with an owned final clock after evidence IO, bind both relevant panels
to one eligibility/epoch snapshot, and make a final STOP/expiry fence before
constructing the response. Keep historical inspection possible. No actual wrong
public prediction was demonstrated; public serving remains disabled for R4.

M1 — HIGH BEFORE LARGE RUNS: allocation happens before overload rejection.
diagnosticFeatureConsumer.mjs:154 calls prepare:73-80, including serialization,
clone and hash, before queue admission:159. A full queue still incurs another
large temporary allocation. Reserve capacity before expensive ownership copying;
use verified immutable handles for duplicate sources. A claimed hash/byte count
must not bypass validation. Rejected overload must not enter the copy/hash stage.

M2 — RUNTIME GATE: cache counts do not bound all live assets in bytes.
featureProjectionCompiler.mjs:32,53,59 and diagnosticFeatureConsumer.mjs:97-138
retain schemas beyond cache eviction in active bundles; journal schema writes
also clone. No common reservation accounts cache, in-flight, reader and encoding
ownership. Introduce shared byte accounting plus lossless compact representation,
not feature pruning. A worker JobObject is not yet a global project supervisor.

H1 — HOT-PATH DEFECT: identical history is fully rebuilt on every live generation.
retainedFeaturePipeline.mjs:188 -> unifiedFeatureProducer.mjs:45 ->
historySourceVerifier.mjs:8-12 -> retainedHistorySourceExport.mjs:50-56.
Frozen history caching does not bypass this repeated source reconstruction.
Use an owned verified artifact handle with exact immutable bindings and bounded
lifetime. Reverify on actual load/reload; do cheap time/identity checks per use.
This is proven redundant source work, not a measured cause of the earlier OOM.

H2 — DORMANT TRAJECTORY DEFECT: corrections can leave old clock arrays selected.
retainedOpenDotaFacts.mjs:74-78 emits no block for times:null/[]/invalid or new
metrics without a clock axis. Old series therefore survive as though no correction
arrived. Current generated vectors do not consume these series. Add versioned
whole-block tombstones and identity epochs BEFORE enabling trajectory features.
Never combine new metrics with an older clock axis or fill retracted data.

E1 — EVENT DEFECT: Aegis receipt order can lose or overwrite episode state.
roshanFeatures.mjs:77-94 marks IDs seen before a terminal-to-pickup link resolves.
An earlier-received consumption followed by a delayed pickup can remain forever
pickup_confirmed. Late contradictory terminal events can overwrite one another;
same-ID changed payload is silently ignored. Use a bounded canonical event ledger
and deterministic episode reduction at the known-at cutoff. Conflicts become
explicit unknowns; absence of inventory never proves a terminal event.
This finding is about implemented optional formulas, not confirmed Steam event
availability. Source qualification remains a separate prerequisite.
