ARCHITECTURE ACCEPTED FOR FURTHER IMPLEMENTATION
One versioned feature producer supplies every phase and target. History is a
separate as-of input, useful in live as well as prematch. Current-map dynamics
come from one coherent admitted source profile, never field-wise provider mixing.
Availability time decides whether a historical fact can be used. Actual game end
time decides recency, decay and sporting streak order. A later download cannot
make an old game recent. Preserve both times and immutable field versions.

History freezes at the first complete draft receipt (t0); later identity disclosure
creates a new context valid at t1 without extending the old history cutoff.
For retained replay, the source frame horizon also limits series/context evidence.
Actual materialization and journal times remain current. Reconstructed vectors
are not originally recorded predictions. Source interruptions reset live windows
while preserving map identity, phase and maximum-clock guards.

All 79 families remain in the catalogue. A large column count does not imply
semantic completeness or source availability. Do not prune proposed features by
univariate correlation or silently replace broad variants with compact models.
Do not require every sparse historical interaction to be nonmissing in 95% of
frames: rare hero/player combinations have genuine support limitations. The 95%
rule concerns jointly available required source inputs for a declared profile and
cohort. Structural hero zeros do not count as observed coverage. Record historical
support/missingness separately and expose no substitute values as observed truth.

R4.0 — FIRST TASK: PAUSES, REPEATED STATES AND FIVE-MINUTE FRESHNESS
Owner-approved direction: preserve the last unchanged forecast during a confirmed
pause; unavailable when qualified state has expired; distinguish an actual pause
from unexplained source repetition. Change the eligible-state age limit to 300
seconds as a provisional product policy, not a measured Steam broadcast delay.
Do not blindly replace every 180-second constant: receipt/state age, evidence
qualification windows and the old absent-phase progression lease are different.

Architecture and required behavior:
1. Keep separate timestamps for last HTTP receipt, last qualified current-state
   confirmation and last game-clock advance. Record the evidence that renewed
   qualification. A new HTTP response, identical cached payload or game_state=5
   alone cannot establish that an upstream state is still current.
2. Confirmed active: accept coherent eligible state, renew its confirmation time
   and recalculate according to the existing cadence. Do not mix source moments.
3. Confirmed paused: require source-backed, temporally qualified pause evidence
   tied to the exact map. Preserve an already issued forecast and its original
   calculation time/state reference; do not invent new dynamics or repeated new
   prediction records because polling continues. A genuinely fresh confirmation
   may keep this paused state eligible beyond five minutes of stationary clocks.
4. Unconfirmed stationary/repeated response: do not infer pause and do not renew
   qualification from receipt time alone. Keep any previously qualified forecast
   only within 300 seconds of its last confirmed state, then show unavailable.
   If the source offers no reliable pause/freshness evidence, retain this unknown
   branch and document the gap; never manufacture a provider field.
5. No usable packets: the same 300-second expiry applies. At exactly 300 seconds
   the prior qualified forecast may still be eligible; beyond 300 it is not.
   A late response cannot retroactively renew an already expired historical state.
6. Confirmed terminal/map change, invalid identity, clock rewind, manual STOP and
   other integrity barriers keep their stricter existing handling; no five-minute
   grace may override them. Preserve original identity/max-clock watermarks.
7. Separate permission to generate a NEW live vector from permission to retain
   an ALREADY issued forecast. The old 180-second progression lease must not be a
   hidden blanket UI expiry for a confirmed pause. Keep initial absent-phase
   qualification and requalification proof requirements explicit; never fabricate
   phase5. After an uncertain gap reset dynamic windows, retaining frozen history.
8. Enforce expiry at reader/API time too, including when the collector is silent.
   Restart recovery must not reset evidence age. Browser users do not drive polls.
   Before inference is enabled, diagnostic tests use explicitly synthetic prior
   forecasts; a feature trace by itself is not an actually issued prediction.
9. Retained offline replay checks age at its verified original source horizon;
   it must not reject all old archive frames based on today's clock or permit an
   arbitrary caller-supplied past timestamp. Keep replay and live serving distinct.
10. User UI remains simple: "Прогноз недоступен" when ineligible. Detailed reasons,
    timestamps and state classifications belong in diagnostic records. No new
    technical warnings or redesign. No training or runtime activation implied.
