FINDING C1 — P1: a completed source-gap poll permanently looks pending
Files: retainedFeaturePipeline.mjs:89-104,218-234;
steamEligibleState.mjs:61-75 (source_gap retains original deadline).

consumeCapture first updates admittedSourceHead for a pinned newer receipt. The
failed-capture branch and the missing-map branch then classify the gap, invalidate
dynamic continuity and preserve the last eligible-state deadline. Neither branch
sets that map's processedSourceKey. readLiveEligibility rejects the old key before
consulting readSteamEligibleState, with newer_committed_source_pending, even after
the execution promise finished and pending==0.

Concrete counterexample:
1. Map M has a committed LIVE trace A and a qualified state with a300-second lease.
2. Thirty seconds later a valid committed HTTP500 receipt, or successful empty GLG
   list, is admitted and fully processed.
3. The eligible-state machine deliberately retains A without renewing its deadline,
   but the pipeline still rejects it as a newer pending source indefinitely, until
   another successful present-map capture marks its key processed.

Impact: one transient missing/failed poll causes immediate forecast unavailability
despite the explicit five-minute retention policy. The rejection reason incorrectly
claims work is pending. This is an availability/state-machine bug, not future-label
leakage or proof that any public serving path was activated.

Decision for Sol:
- Track latest admitted source head and per-map fully classified source head
  separately. The latter must advance after EVERY successfully classified outcome:
  changed eligible state, repeated state, confirmed terminal, integrity rejection,
  ordinary source gap, and a valid committed failed response.
- While a newer head is genuinely unclassified/queued, keep fail-closed fencing.
- After classifying an ordinary gap, read the owned eligibility state and original
  trace/observation/deadline. Do not renew time or generate a new vector.
- Terminal, changed-known identity, STOP, clock rewind and invalid proof remain
  barriers. Never blindly advance a head for unverified bytes or failed classification.
- A queued head C cannot be accidentally acknowledged by older executing head B.
  Final head and epoch comparison remains synchronous after asynchronous IO.

Required acceptance cases (small synthetic state-machine tests, then affected
integration scope; no model fitting):
- Actual pipeline A -> HTTP500 B, A -> absent-map B, A -> empty-list B; after B
  settles, retain A at299s and reject at301s; lastConfirmedAt never changes.
- A -> repeated identical-clock B: same retained trace/observation and deadline.
- Block B during IO, admit terminal C, finish B: A/B cannot become eligible.
- C fully classified terminal/known-identity conflict: rejection persists.
- Two maps in one source response: missing M keeps only M's original retention;
  present N uses its correctly classified state. No cross-map head substitution.
- Restart replay and manual STOP preserve existing barriers and never renew time.

FINDING C2 — P1: static current-authority stamp is not bound to the input
Files: staticDiagnosticWriter.mjs:17-25,35-44,60-63;
retainedStaticHistoryView.mjs:14-24;
staticDiagnosticWriter.test.mjs:54-67.

The writer reads a current stamp using only mode/decisionAt/mapId/seriesId, then
compares that stamp before and after IO. It never compares the stamp's
identityRevision, seriesRevision, sourceGeneration or targetGeneration with the
actual private static proof/component. An already stale proof for the SAME map or
series can therefore be calculated while a stable newer authority stamp is returned
both times, and the receipt reports currentAuthorityVerified:true.

Current tests cover a stamp changing DURING IO. They do not cover a stale candidate
at ENTRY while the current stamp remains unchanged. The rich integration fixture
closes its authority callback over the expected proof values, so it cannot expose
this mismatch either. This does not show wrong public predictions: the path remains
diagnostic and no inference output is created.

Decision for Sol:
- Derive a typed expected authority identity from the actual private proof:
  mode, map/series ID, transition ID, identity revision, target derivation reference,
  exact series receipt, source view/facts bindings and immutable history cutoff.
- Obtain the current host authority for that entity, validate its shape, and require
  expected==current BEFORE expensive generation. Repeat after each required IO
  boundary and immediately before issuing a current receipt.
- Use typed fields, not arbitrary strings where sourceGeneration sometimes means
  corpus manifest and elsewhere facts hash. Define both explicitly if required.
- The active effective as-of source view is the correct historical identity. A
  global source generation advance consisting only of post-cutoff/unrelated facts
  should not automatically invalidate an otherwise identical frozen view; preserve
  exact facts/view identity and explicit correction epochs.
- Forensic stale inputs may be persisted only via a separately named mode whose
  currentAuthorityVerified is false. Stable-but-unbound stamps are not verification.
- Never weaken private proof ownership or substitute names-only schema identity.

Expected authority fields must keep THREE meanings distinct:
1. FrozenHistoricalBinding: the actual proof's generationReference, target-specific
   sourceSnapshotHash/envelopeReference, factsSha256, targetSha256, seriesSha256,
   targetDerivationReference, cutoff/validFrom and any native generation/view binding.
   These identify what was used. They are NOT the current capture receipt generation.
2. ActiveTargetBinding: the host's currently selected map/series/transition and
   authoritative identity revision, exact target/series receipt and approved frozen
   historical binding for this decision. Match the candidate against this binding
   at entry and after IO. A stable host stamp for a DIFFERENT frozen binding fails.
3. CurrentSourceFence: the current observation/classification/progression/terminal
   epoch, evaluated at owned now for LIVE. It can advance while the historical
   cutoff and its approved frozen inputs stay fixed. PRE/BETWEEN use their own
   target/series event authority; they need no fabricated live capture generation.

Do not equate generationReference, sourceSnapshotHash, factsSha256 or a live receipt
key merely because all are hash-like strings. Initially the host can select an
explicit existing immutable historical proof: match its exact bound references.
If later allowing reuse across corpus generations, require an explicit verified
equivalence result over effective facts, identity and cutoff, including corrected
versions; a newly exported descriptor with different timestamps is not byte-equal
and must not be waved through by matching only factsSha256. Record the actually
used generation even when such equivalence is independently established.

Required acceptance cases:
- Stale target derivation, roster revision, series receipt/transition and source
  view, one at a time, already stale before consume; unchanged current stamp must
  reject before generation/storage as appropriate.
- Matching proof and stamp passes; mutation/terminal/STOP during IO still fails
  closed while preserving any already committed forensic artifact.
- Wrong same-ID series score or draft correction does not pass stable authority.
- Irrelevant source append after frozen cutoff with identical effective view is
  explicitly either reusable under the defined contract or rebuilt, never guessed.
- Test native/private retained proof path rather than only a fake producer whose
  authority callback uses the same fixture variables.

EVIDENCE / ARCHITECTURE GATES THAT ARE NOT IMPLEMENTATION BUG CLAIMS

G1. Native-history availability is not automatically populated by existing raw files.
createRetainedMapHistoryHost requires an explicit nativeSourceHandle; bootstrap
merely forwards boundedHistory arguments (retainedDiagnosticBootstrap.mjs:48).
create/restoreRetainedNativeHistorySource callers found in focused source are the
library and tests, not a deployed background orchestration path. The final all13
fixture does not establish real populated economy baselines. Sol must build an
offline intake manifest from retained raw+receipt pairs, bind matching as-of prior
facts, record every rejection and quantify coverage. No new provider requests or
task activation are needed to audit existing retained evidence.

G2. The only admitted current rich profile here is
steam.GetLiveLeagueGames.v1.scoreboard. Other Steam endpoints/shortened realtime
packets do not become equivalent merely because both are Steam. Keep separate
profile contracts; add an endpoint only after field/clock/identity equivalence and
availability evidence. Retain absent values, literal opaque native fields and
separate rules/event evidence. Source95 means present and timely JOINT input
coverage for a declared required profile, not masked structural hero zeros.

G3. A source gap policy needs separate short fast observation classification and
heavy feature generation. All13 cold LIVE operation was about250s. With continuous
new polls and the global admitted head fence, every long in-flight bundle may become
superseded before commit. Do not remove fencing to make it pass. Sol should retain
all source receipts, classify in bounded arrival order, coalesce only pending heavy
generation to latest eligible state, precompute unchanged historical blocks and
specify an observable maximum lag. Root/storage review designs the actual bounded
scheduler and fast path. Offline replay can remain exhaustive and slower.

G4. Fully known account identities are currently required in PRIOR native snapshots
for a hero-only economy baseline (historicalAlignment.mjs:42-48 and
historyCalculationCore.mjs:79-87). The CURRENT target may be anonymous, as the
existing test covers. Missing prior accounts therefore reduce usable history even
when map/side/hero/metric is known. This is conservative missingness, not leakage.
For later coverage work, allow hero-only baselines without public accounts only
under a separately defined map+side+hero coherence proof; player/role baselines
must keep account identity requirements. Measure retained coverage first, preserve
distinct semantics and do not silently relax the existing source contract.

G5. No current source proves a true pause or event-to-app latency. Current policy
allows300s retention, distinct180s absent-phase progression qualification, and
forbids renewed freshness from a repeated HTTP response. That distinction is sound.
A fresh confirmed pause capability requires actual source evidence; do not invent
it from stationary game clocks or imply a five-minute provider transmission lag.

G6. Same known source values at different receipts, corrected values, NULLs and
identity transitions must remain in the version ledger. A later validation rule can
validate old facts retrospectively, but it must not change their original knownAt
or turn retrospective computedAt into a recorded prediction. Each output should
keep availabilityBasis and separate fact input cutoff / identity validity /
materialization ready / source receipt / current read time.

PRIOR-NATIVE PROVENANCE DECISION AND ACCEPTANCE MATRIX
The first offline intake uses only actual retained raw bytes plus their recorded
normalized observations and capture receipt metadata. Source manifests preserve
every supplied version; target-specific views choose qualified prior observations.
Raw capture hashes, re-normalization, same-map identity, completion fact versions,
availability cutoffs and rule-policy pins all remain explicit. Existing directory
mtime or the intake run's time cannot manufacture historical availability.

Case | Required disposition
Raw/normalized mismatch or false observation ID | Reject; preserve exact reason.
Target map offered as historical map | Reject, regardless of earlier game clock.
Prior final outcome/duration/heroes/accounts learned after cutoff | Reject for that cutoff.
Recorded raw state received after cutoff | Reject for that cutoff; can serve a later cutoff.
Final parsed statistics with no original live state bytes | Never use as live native state.
Explicit valid raw in-progress phase and all temporal bindings | Admit diagnostic prior reference.
Absent raw phase, reviewed profile and pinned independent interior-clock alignment |
  Admit only reconstructed reference according to explicit policy; raw phase stays absent.
Absent phase with no externally selected profile review hash | Reject; candidate cannot self-approve.
Alignment/profile review created after receipt | Record later validation/computation time;
  do not rewrite source receipt or imply a recorded historical prediction.
Duplicate same observation and same bytes | Deduplicate per stated identity, retain audit count.
Same observation identity with different bytes | Hard conflict, not last-write-wins.
Anonymous prior accounts | Current contract rejects; keep this baseline separate from
  optional future hero-only contract. Never fabricate account IDs.
Current source disappears while prior corpus remains available | Prior context alone
  cannot satisfy current LIVE eligibility; follow C1 lease and terminal rules.

The intake report must state supplied/selected/rejected counts, distinct maps,
original receipt date span, valid profile/phase basis, account coverage, per-minute
support and why missing baseline values remain missing. It must demonstrate at
least one actual retained prior-state-to-target-proof binding or explicitly report
zero eligible rows. No fixture count substitutes for this real retained evidence.
