1. WHAT IS USEFUL
index.ts exports separate dictionaries for heroes, abilities, hero-ability slots,
items and item IDs, Aghanim descriptions, buffs, XP thresholds, maps of regions/
clusters/game modes and patch metadata. These can support deterministic ID joins,
hero mechanics/item predicates and correctly qualified draft/economy interactions.
They do not supply historical player form, actual player positions or match events.
https://github.com/odota/dotaconstants/blob/5c0242df9057848fa2036ca3fafe9f2bd4508163/index.ts

2. CURRENT SNAPSHOT IS NOT A PER-HISTORICAL-MATCH RULESET
The builder obtains current extracted game files and game data, transforms them,
then writes build/*.json. Manually maintained json files are copied into build.
No invocation of the builder was made here. Its source references include remote
datafeed URLs; reading code is not permission to run those calls.
Historical use needs a pinned matching game-rule version and availability policy.
Applying today's item costs/hero attributes to all old matches changes feature
meaning and can introduce retrospective information. Commit time is a provenance
timestamp, not proof of exact game deployment or of what Aegis knew historically.

3. PATCH LETTERS ARE NOT COVERED BY THIS PATCH-ID TABLE
build/patch.json has61 entries, ending base7.41/id60 dated2026-03-24.
No entry name in that pinned table ends in a letter. This does NOT establish the
current Valve patch and cannot distinguish7.41a/b/c/d/e in Aegis history.
newpatch.ts appends a numeric+0.01 name, current wall date and sequential ID.
Keep calendar-inferred patch intervals separate from observed game build/rules;
do not assign tournament match patches with absolute certainty from this table.
The owner's letter-aware patch contract still needs separate release/rule evidence.

4. HERO ROLES AND A CONCRETE NAMING TRAP
At this snapshot build/heroes.json has127 keys. roles comes from the game hero's
Role tag list. Carry/Escape/Nuker-style tags are hero capabilities, not proof that
the currently selected player is position1,2,3,4 or5. Economic rank is separate.
The builder sets attack_rate from AttackRate, but base_attack_time from
BaseAttackSpeed. A sampled Anti-Mage entry has attack_rate1.4 and
base_attack_time100. Do not interpret the latter as seconds merely from its name.
Use exact upstream binding/units, or mark the source unqualified until resolved.
This is a source-code finding, not an Aegis runtime bug or a claim about actual
attack rate after items/buffs. No derived power formula was installed.
https://github.com/odota/dotaconstants/blob/5c0242df9057848fa2036ca3fafe9f2bd4508163/tasks/updateconstants.ts#L1938-L2009

5. ITEM/AEGIS RULE CANDIDATES
Pinned items dictionary has501 keys. Aegis entry has itemID117, cost0, separate
reincarnate/disappear timing attributes including ordinary300s and turbo240s.
These provide a rule candidate for a qualified matching mode/patch/item protocol;
they do not prove current possession, pickup age, steal or Roshan death time.
Use actual Steam item IDs and event evidence; do not sum an incomplete six-slot
inventory to replace a provider's complete native net worth. Current item cost
cannot reconstruct total historical spending, sale losses, consumption or transfers.
Only a summary of this dictionary entry is reproduced; no game assets copied.
