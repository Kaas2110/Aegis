AEGIS — USER-SUPPLIED STEAM DOCUMENTATION REVIEW
26 October2026. Read-only documentation/source research; app and training unchanged.

ANSWER
Documentation exists, but the supplied materials cover different layers: official
method discovery, third-party API clients, a separate commercial data service and
replay-parser implementation. They are useful when bound to exact method/version,
field path and source horizon. None establishes one universal economic field map
for all Steam, OpenDota and other providers.

The owner and architecture agree: canonical netWorth is current inventory value
plus wallet, can decrease, and is the main current-economy measure. Total earned
gold is different. Our uncertainty concerns specific raw gold/net_gold mappings,
not whether net worth is useful or how the canonical net-worth metric is defined.

5. Cito API
https://citoapi.com/docs/api/dota-2/#match-centers
Its own service uses api.citoapi.com and x-api-key; it advertises live schedules,
series/maps, player statistics and normalized radar measurements. This is not
Valve's specification for our existing Steam key. The match-center section also
describes post-match pages. No Cito account, key, purchase or data call was made.
Its marketing/API vocabulary is not evidence that it supplies every field needed
by Aegis at the same game clock or lower delay.

7. OpenDota primary source investigation
https://github.com/odota
The replay parser separately reads m_iNetWorth and m_iTotalEarnedGold, with
networth_t and gold_t outputs. This is meaningful positive evidence for historical
feature mappings, but does not imply identical raw Steam key names across methods.
The deeper core/parser/availability/constants study is recorded separately with
specific commits and decisions. It supersedes any broad claim that all OpenDota
economy fields are opaque; uncertainty is now source/version/field-specific.
