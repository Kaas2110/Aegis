A. DEFINITIVE SOURCE ARCHITECTURE
A1. Historical facts: local retained OpenDota completed-map records, plus separately
retained Steam observations from PRIOR maps where needed. Read the local versioned
store. No OpenDota HTTP call in the decision-critical live feature path.
A2. Current dynamic state: one admitted Steam.GetLiveLeagueGames.v1.scoreboard
observation and its causal same-map/source/identity prefix. Current selected hero
IDs may be known when accounts are anonymous. No mandatory STRATZ dependency.
A3. GetRealtimeStats is a separate optional profile, not a bag of extra columns to
merge into GLG. It needs an independent field/equivalence/coverage contract. Do not
borrow its newer clock and combine it with an older GLG player's GPM/items.
A4. Retrospective OpenDota curves remain their own profiles. earned gold gold_t,
final gold_per_min, net worth and current native GPM are different quantities.
Past final statistics CAN describe an old player's form; current-map finals CANNOT
replace live measurements. A match-detail endpoint is not arbitrary-time replay.
A5. Existing production OpenDota serving, with dormant optional STRATZ detail
enrichment in the inspected worker, remains a separate old route until
a qualified replacement is explicitly activated. This is the target architecture,
not a claim that source installation already switched production to Steam.

B. CANONICAL INPUT MEANINGS AND AVAILABILITY
B1. H = prior-map facts: matchId, endedAt, outcomeKnownAt, durationSeconds,
radiantWon, radiantTeamId/direTeamId, heroes/players with per-field knownAt,
side kill totals, heroPerformances.metrics and their field receipt lineage.
Normalize side by explicit roster, never array position. End time determines form
recency; actual local field receipt determines whether it can be used.
B2. V = current normalized Steam observation: matchId, observationId,
providerGameClockSeconds.value, source.capture.receivedAt/rawSha256,
dynamic.sourceProfile/phase, sides.{radiant,dire}.teamId/score,
players.identity.{accountId,heroId,teamId,side}, players.netWorth,
goldPerMinute, experiencePerMinute, level and observedItemFields.
Raw GLG paths are result.games[i].scoreboard.{radiant,dire}.players[j].
net_worth/gold_per_min/xp_per_min/level/item0..item5. Identity matching is mandatory.
Game clock binds to result.games[i].scoreboard.duration; team IDs bind to
result.games[i].{radiant_team,dire_team}.team_id -> sides.{side}.teamId.
Preserve raw paths and validation receipts, not a name-only alias.
Steam side.players[j].death maps to sides.{side}.players[j].dynamic.deaths;
historical OpenDota deaths is
a different source field. Both represent observed counts, not missing-as-zero.
B3. Dynamic extra fields have separate semantic evidence: kills/death/assists,
last_hits/denies, position_x/y, respawn_timer, ultimate_state/cooldown,
has_buyback/buyback_cooldown, scoreboard.roshan_respawn_timer. Retaining a raw field
is not proof of units, sentinel meaning, availability or mechanical interpretation.
B4. D = observed draft/identity revision and its original receipts. Ten selected
heroes may suffice for postdraft; ten disclosed account IDs are not required.
Unknown account suppresses account-conditioned terms, not hero identity terms.
B5. S = versioned series receipts: seriesId, nominal team1/team2, BO format,
complete prior-map prefix, per-field availableAt, current map/side mapping when
known. PRE series needs neither an invented map ID nor Radiant/Dire assignment.
B6. E = qualified same-map event ledger with event ID/type, gameTimeSeconds,
knownAt, source and episode links. RULES = versioned patch/source rule table with
evidence and knownAt. Neither can be minted from a postgame label for early live.
B7. A = prior native frames/trajectories: raw+normalized+alignment receipts,
match identity, source profile and actual time. Bounded history currently sends
this modality empty; plugging it in is required, not a new API assumption.
B8. New logical inputs proposed below (role evidence, patch-specific mechanics,
event histories, native geometry) are input CONTRACT requirements, not claims
that a current Steam endpoint supplies them. If unavailable, return typed missing.

Time policies, shared by every family:
- PRE map: current target identity available at its decision, historical cutoff
  explicitly bound to that target; no selected current heroes or dynamic values.
- POST/LIVE: history cutoff t0 is first complete retained draft receipt. Later
  account/side identity t1 changes selectors and validFrom, never expands t0.
- SERIES_PRE: first known series/roster context and its own cutoff; BETWEEN:
  versioned completed-prefix transition and its own cutoff. For a live series,
  independent series history retains its series-transition cutoff; reused map
  history retains map t0. Prior-series fields must be available by sourceDecision.
  These are three distinct horizons, not one unqualified shared timestamp.
- Old completed match first received today may enter tomorrow's history. It may
  not be backdated into yesterday's recorded forecast. Original provider publication
  time, locally witnessed receipt, later reconstruction and field equivalence are
  separate evidence classes; missing original publication is not a blanket ban
  on future use after a real local receipt.
- Reconstructed offline rows carry source/event cutoffs and actual materialization
  time separately. No assertion that the application issued a past forecast.
- Current frame must pass identity, phase/progression, terminal, clock/STOP and
  currentness checks; 300s retention is distinct from 180s qualification.
- Recheck authority after awaited work. Computation start is not computation-ready
  time. Receipt freshness is not demonstrated event-to-app latency.

C. EXACT SHARED STATISTICAL TEMPLATES
C0. C1-C13 specify current v3/new canonical variants, NOT replacement definitions
for pinned legacy inputs. The companion legacy map takes precedence for old
weights: preserve K24 versus K32, different priors, 180-day/lifetime/deque scopes,
availability-aged versus endedAt-aged decay, population versus sample SD, and
source-specific trajectory windows. Different meanings require separate IDs.
C1. Historical cohorts are distinct maps, selected by team/account/hero/opponent
identity known at cutoff. Windows W in {7,30,90} days use endedAt in [cutoff-W,cutoff].
Do not label this 90-day implementation lifetime. Lifetime is a separate full-history
variant only after a bounded implementation and support evidence exist.
C2. n=count distinct qualifying maps; y=own-side win. rawWR=sum(y)/n;
betaWR=(sum(y)+10)/(n+20). w_i=2^(-ageEndedDays_i/W);
decayWR=sum(w*y)/sum(w); betaDecayWR=(sum(w*y)+10)/(sum(w)+20);
nEff=sum(w)^2/sum(w^2). These four probabilities are distinct features.
Beta(10,10) is a fixed reference prior, not a learned estimate of current meta.
C3. Means are arithmetic mean over the exact supported subset; sample SD uses
n-1; empirical quantile interpolates index (n-1)*q. Roster/profile population SD
uses the number k of actual finite members (five only for a complete team).
Some legacy historical/style SDs also use population divisor n. Preserve their
pinned definitions; do not relabel them sample SD or restrict ddof0 to live teams.
Wilson95 uses z=1.959963984540054. A Wilson interval is descriptive uncertainty,
not proof of independent matches/series or a deployment probability interval.
C4. Conditional win/loss-duration and available-kills means have their own support
denominators. Mean of per-map kills/minute != sum(kills)/sum(minutes). The current
aggression proxy is the former; preserve its name and never call it attack intent.
C5. Counts/support return observed zero for an empty qualified cohort. Statistical
values require the exact pinned minimumSupport; variance needs >=2 and positive
scale for z. Freeze existing minimumSupport parameters in schema. New conditional
variants use minimumSupport5 initially, with count/nEff exposed. Current history
uses context minimumSupport M, default5. Only playerLateTendency, heroLateTendency
and playerHeroLateTendency require max(5,M); current team lateTendency and relational
late40/late50 fractions retain their pinned M. Preserve each existing parameter.
Literal identity, known roster and fixed initialization
do not need five historical maps. Do not silently raise existing thresholds or
expose a prior-only0.5 as measured form at n=0.
C6. Structural unpicked-hero zero is allowed only after a complete draft. Unknown
selected-hero measurement is null+mask. Product involving a missing operand is
missing even if another operand is zero; ratios need positive denominators.
Maintain explicit missing reasons: unavailable_field, unverified_semantics,
no_history, below_support, zero_variance, incomplete_roster, stale, wrong_phase,
missing_rules, identity_conflict, unavailable_at_cutoff, outside_profile.
C7. Side orientation: map scalars Radiant minus Dire; hero one-hots signed+1/-1;
series scalars team1 minus team2 using explicit current side mapping. Do not
copy map probability into series probability. IDs are nominal, never strength.
C8. Historical current-minute normal: one preceding qualified frame per prior
map/hero/minute, clock<=60*m and within30s; same source metric, raw proof and
cutoff. Current implementation bins by ceil(clock/60); live selects greatest
m<=floor(currentClock/60) within5min. Expose referenceMinute/referenceAge, support,
mean and sample SD; raw residual=x-mean, raw z=(x-mean)/SD. Emitted signed hero
columns multiply these raw values by that hero's side sign. This is a lagged-minute reference,
not necessarily exact-minute strength. Preserve current version; new tighter
reference variants get separate IDs. Never use a future-nearest frame or gold_t
as native NW. Patch/role stratification is separate and requires evidence.
C9. Native v3 two-point trajectory: latest earlier frame at/before currentClock-window with
max30s anchor gap; divide changes by ACTUAL elapsed minutes. Use same identity/
source prefix, respect resets/corrections/gaps. Current windows60/180/300/600s
remain exact; new120s version is additive. Repeated clock is not extra progress.
Old observed268 uses 120s anchor slack, not this 30s policy. Full-prefix window
aggregates are a separate template, not two-point slopes. Preserve each legacy pin.
C10. Learned transforms, target encodings and model priors need TRAIN/fold/series
split/state pins. Build within each forward fold; no future label contamination.
Raw deterministic history also obeys event/receipt cutoffs. Tune only later.
C11. Units compose algebraically: x*minute has x-unit*minute, x*probability keeps
x-unit but preserves fraction provenance; x*y has both units. Difference requires
same metric/unit/population definition; z/rank and same-unit ratios are dimensionless.
A general ratio has numerator-unit/denominator-unit. No mystery
unresolved_historical_units in an admitted projection.
C12. New synergy variants use betaWR(A,B)-[betaWR(A)+betaWR(B)]/2 as marginal excess,
not causal synergy. Directed counter variant is betaWR(A vs B)-betaWR(A).
An optional balanced counter subtracts [betaWR(A)+1-betaWR(B)]/2 instead;
it needs a different ID and all operand supports/windows/populations pinned.
Difference-in-differences variants keep each four cohort IDs/supports. Current
rawWR differences remain separate, not silently renamed smoothed variants.
C13. New chronological result-rating reference: R0=1500,K=32,scale400,
p=1/(1+10^((Ropp-Rown)/400)), update own+=32*(y-p), opponent symmetric. No automatic
patch reset. Team ID rating and player-lineup result rating are separate. Player
variant compares mean of five KNOWN account ratings and updates all five by the
same residual; missing full roster skips that update. This measures lineup results,
not personal MMR/mechanical skill. No fabricated rating uncertainty; expose support,
recency/roster coverage. This deterministic state is prepared/replayed causally,
with no state generation or fitting executed by this review.
Pin source population, generation, history origin and genesis/prior rating state.
Replay by endedAt then numeric map ID ascending; both sides update from the same
pre-result state. Corrections trigger causal replay. Unknown team/full-roster
identity skips the affected update. Expose a measured rating only at own support
>=5, and paired expectation only when both qualify; the internal fixed prior is
not observed strength. Existing K24 variants remain unchanged legacy definitions.

D. ALL 79 FAMILY DECISIONS
Each entry gives meaning and necessary inputs. The time/support/missing/source
rules above apply; exact emitted templates must name the concrete operand paths,
not just the family ID. Existing values are preserved unless an explicitly named
bug or versioned new variant below changes their contract.

I01 Identity: H/D/S/V account,hero,team,side and roster identity; hashes are binding
metadata, not continuous model inputs. Nominal hero/player/team encodings explicit.
I02 Disclosure: known-account/team flags, disclosed counts and fractions over the
ten observed slots, identity validFrom and coverage. No invented account ID.
I03 Role: evidence-backed farm role1..5 separate from economic ranks1..5 and
historical lane categories1..4. Unknown roles stay missing; never infer carry from NW.
I04 Context: BO1/3/5,winsNeeded,mapNumber,rest days since last completed map,
prior7/30d map counts, versioned league/tier/region. Unknown map/sides allowed PRE.

H01 Team strength: C13 team result rating, support, recency and paired expectation.
Historical record may span patches; patch identity separate; no claim of intrinsic skill.
H02 Team form: C1/C2 team win rates, signed streak ordered endedAt then numeric mapId,
7d-minus30d and30d-minus90d raw/weighted differences, each operand separately named.
H03 Head-to-head: directional team-pair win rates/support, and mean(y-p_pre)
using a provably pre-map rating expectation. No p reconstructed using that game's result.
H04 Roster: intersection/5 and Jaccard with last known roster; distinct shared-map
count and days since observed roster change. Missing roster is not a new lineup.
H05 Player form: account win rates7/30/90d, paired roster summaries with known-count.
Mean/min/max/populationSD(k finite players)/quantiles describe historical result
rates, not MMR. A sample-SD alternative needs its own ID.
H06 Player-hero comfort: account+hero raw/smoothed rates30/90d, pick share=count
account maps on hero/count account maps with observed hero, days since last pick.
Lifetime scope reserved until available; account+hero != hero population.
H07 Player result rating: C13 known five-player lineup update, player support and
recency. Do not use per-map final GPM as a rating target or call result rating MMR.
H08 Performance: past native GPM/XPM,totalGold,totalXp,NW,goldSpent,K/D/A,LH/denies,
damage/healing/wards and per-duration rates. Native source-field mapping is in
historicalPerformanceFields.mjs. KDA=(K+A)/max(1,D); damagePerGpm=(damage/min)/GPM.
H09 Hero-adjusted form: account-hero mean minus own-account mean or hero-population
mean; divide only by that population sampleSD for z. Preserve population/window/
native metric. Current formulas use rawWR/unweighted means; C12 variants additive.
H10 Team-player-hero fit: conditional team/account/hero means and differences;
(account-team-hero minus account-team) minus (account-hero minus account).
H11 Resource/output style: old damage/min,GPM,deaths/min ratios, each exact metric;
damagePerGpm is output per earned-gold rate, not fighting strength. Ward counts may
describe vision activity, not actual map control; no invented latent-style label.
H12 Matchup summaries: all25 opposing player comparisons of the SAME supported
metric: xAi-xBj, available-pair count, population SD over available comparisons
and quantiles; role pairs require I03. These are not 25 independent historical maps.
H13 Team duration tendency: duration mean/sampleSD/q25/q50/q75; raw tail fractions
>=40 and>=50min; additive threshold curve25..80min in5min increments. Winning
duration is conditional on wins, not conditional on a live gold lead.
H14 Player/hero/player-hero duration: three distinct C1 cohorts and tail fractions;
hero population includes anonymously played known heroes, not only target accounts.

D01 Draft identity: explicit selected heroes per side, signed one-hot, known flags;
ban/order/slot features only from explicit received evidence. Supported1..250 range
is an adapter dictionary, not a claim of250 currently available heroes.
D02 Hero meta: pro-population win/pick rates7/30/90d, side and support; bans need
complete observed ban denominators. Pick share = maps containing hero / maps with
complete ten-hero drafts, not ten times that denominator. Ban share uses maps with
complete explicit ban lists and the hero eligible under known patch rules; maps
without that evidence are outside this denominator. Report eligible coverage.
No account-filtered sample labelled global meta.
D03 Ally heroes: unordered pair identities and raw conditional means, C12 marginal
excess as an additional version. Pair symmetric, opposing pair directional.
D04 Hero counters: A-vs-B directional rates, directed support and separate C12
counter excess. Known ban removes only that opponent option; no invented pick intent.
D05 Team hero pool: team+hero rates/selection share, roster comfort distribution;
team share = team maps selecting hero / team maps with complete five-hero draft,
not five times that denominator. Undrafted PRE summaries never select future heroes.
D06 Patch meta: D02 computed within a proved letter-patch ID plus base-patch ID;
knownAt-aware7/30/90d trends. Calendar-inferred patch is a separately named confidence
profile; never overwrite explicit patch or assume same mechanics across letters.
D07 Population meta: Immortal/rank/region/role rates only for that retained population
with defined denominator. Current pro data cannot masquerade as Immortal data.
D08 Mechanics descriptors: patch-valid hero/ability/item descriptors (push, control,
save, mobility, scaling) from evidenced versioned rules. No numeric power weights
invented from hero names. Unknown/unversioned mechanics are unavailable, not zeros.

P01 Player allies: accountA+accountB on same side conditional result/performance,
unordered key and each individual's marginal baseline; C12 excess distinct.
Pair performance means the mean of both players' SAME metric, both required.
P02 Player-hero plus ally player: accountA/heroA/accountB conditional means;
performance is focal accountA's metric; subtract accountA/heroA baseline; do not
condition on the ally's future hero in PRE.
P03 Player-hero plus ally hero: accountA/heroA/allyHeroB means minus accountA/heroA
and separately minus heroA+heroB baseline. Performance is focal accountA's metric;
those baselines and their populations are different columns.
P04 Two player-hero pairs: symmetric allied (accountA,heroA),(accountB,heroB) key;
allied performance averages both same-metric values, both required. The directional
opponent variant uses A-minus-B. Support distinct maps, not pair rows. Outcome
cohorts require identities and outcome; performance cohorts additionally require
their exact metric operands, with separate support counts.
P05 Opponent/compound matchup: account-hero versus opposite account-hero, explicit
triples and mechanically evidenced archetypes. Retain individual main effects.

S01 Pace proxy: mean per-map kills/deaths per played minute; early kills/engagements
only with timestamped prior prefixes. Final rate is not known early current-game rate.
Team deaths require the sum of all five native player death counts; do not substitute
opponent team kills. A partial roster sum must have a separately named contract.
S02 Item/vision habit: prior purchase-time distributions for evidenced item IDs,
ward counts/rates, buyback counts when observed. Missing purchase is censored/not
observed, never zero-second timing; absent event log is not no purchase.
S03 Style matchup (new): at each prior match freeze opponent's pre-match30d pace;
compare to target opponent pre-match pace. Weight prior result by recency times
exp(-abs(pace_i-pace_target)/0.25), pace in team kills/minute; emit sumweight,nEff,
weighted result and weighted(y-p_pre). This is an explicit reference kernel, not
learned ground truth. A richer style vector is a separate TRAIN-scaled variant.
The old 20-stat Gaussian style kernel is a distinct preserved legacy formula.
S04 Draft/style fit (new): fit_z(T,D)=sum_h[mu(T,h,z)-mu(T,z)]/5 over selected
heroes. z is explicitly total-map kills/minute, duration minutes or late40 flag;
team-hero and team populations use the same frozen window. All five terms and
their marginal baseline require support>=5; expose supports and raw operands.
Comparing global hero means to team mean would be a separate variant, not this fit.
Mechanics-based archetype fit requires D08.
S05 Closing (new): at prior10/20/30-minute landmarks select preceding frame<=minute,
max30s gap. For lead>=1000 native team NW emit eventual win fraction and remaining
duration distribution; for deficit<=-1000 emit recovery/win fraction. Use prior maps
known by cutoff. Thresholds reference variants, not a universal Dota rule; include
landmark/lead support. Early-ended maps not in that landmark risk set.
S06 Form x current trajectory: supported player/team/hero form times current lead,
recovery, retreat and actual-minute momentum. A recovery is a measured prefix
movement, not a label that the future comeback will succeed.

R07 Contest capacity: live positions/alive/items/ultimates plus known objective
