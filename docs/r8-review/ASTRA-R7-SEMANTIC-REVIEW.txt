1. WHAT THE 9,952 LIVE GAPS ACTUALLY MEAN

The saved final all13 audit reports 9,232 unverified native plus 720 unbound
parameter occurrences in EACH of four LIVE heads. They are repeated vocabulary
occurrences, not 39,808 independent new concepts. Static generator grammar gives
this exact decomposition, consistent with the recorded family totals:

  Native opaque branches                                     Count per LIVE head
  hero native_gold observed_value, 250 dictionary slots                       250
  hero net_gold_raw, 250 dictionary slots                                    250
  native_gold hero-minute residual and standardized, 250 * 2                 500
  native_gold * 8 frozen context fields * 2 variants * 250                 4,000
  native_gold team interaction, 3 sides * 8 contexts * 3 terms                 72
  native_gold economic-rank interaction, 2 bases * 5 ranks * 2 sides * 208   4,160
  Total                                                                   9,232

The 208 profile keys are 16 nonperformance keys plus 32 historical performance
metrics times 6 profile transformations. Root's saved audit has L02=500,
L06=500, L14=8,232 native gaps, exactly matching this expansion.

This is NOT 9,232 missing mathematical descriptions. Their arithmetic is already
specified. The unresolved fact is the physical meaning of Steam player.gold and
player.net_gold under the current profile. describeNativeEconomyOperand preserves
them as provider_gold_raw/provider_net_gold_raw (playerHeroEconomyFeatures.mjs:13-18),
and nativeFieldEvidence.mjs:5-6 explicitly calls their units unverified. No current
evidence justifies substituting netWorth, earned total gold, goldSpent, or GPM.

ASTRA DECISION S1: preserve every occurrence in inventory and forensic diagnostics;
record formulaStatus=specified_literal_algebra, sourceMeaningStatus=opaque_provider,
candidateDisposition=diagnostic_only_unqualified_source. Every dependent product,
residual and standardized value inherits that source limitation. A model profile
must not silently admit these branches merely because the dependency description
is complete, nor silently delete their vocabulary. An observed raw zero remains
observed raw zero; an absent/invalid input remains missing. The 240 unpicked hero
slots cannot make active selected-hero coverage appear complete.

Literal opaque ultimate/position/timer/buyback fields need the same TWO-AXIS
classification. dynamicSemanticBindings.mjs:6,37 currently binds them without
setting opaque, and so labels their literal transforms authoritative_template.
That may describe faithful copying, but it is not certification of cooldown
seconds, enum readiness, map coordinates, alive state or buyback feasibility.
Keep raw diagnostics; admit interpreted gameplay features only under exact proved
source/rules semantics. Do not relabel them unavailable at the endpoint: the
missing evidence is their interpretation, not necessarily field presence.

2. EXACT RESOLUTION OF THE 720 PROGRAMMING GAPS

observedDraftFeatureBundle.mjs:274-284 computes nine trajectory statistics for
5 lead metrics, 4 windows and two sides. Each is multiplied by one of three
EXPLICIT team profile keys: formWinFraction30d, late40Fraction90d,
winMeanDurationSeconds90d. The numeric code selects that same-side team row.
The descriptor instead puts d.definition into historyDefinitions. This is an
operator template ID, not an operand address.

dynamicSemanticBindings.mjs:16-25 indexes every players/teams/heroes statistic by
both key and generic definition. Its identity comparison includes key/window.
Generic rawWinFraction matches 7/30/90-day and multiple profile keys. Generic
late40Fraction matches team/player/player-hero/hero keys. Each of those two
ambiguous templates occurs 5 * 4 * 9 * 2 = 360 times, totaling 720. The win-duration
team key does not collide in the same way. This count is a source-derived
reconciliation, not a newly executed full audit.

ASTRA DECISION S2: keep current arithmetic. Bind each trajectory product to an
EXACT typed historical-statistic reference (details in FORMULA-CONTRACTS.txt):
  component=relational; profileKind=team; side=the emitted side;
  selector=current same-side teamId; key=formWinFraction30d or late40Fraction90d
  or winMeanDurationSeconds90d; window=30/90/90 respectively;
  operator=rawWinFraction/late40Fraction/winMeanDurationSeconds;
  formulaVersion=aegis.prior-map-relational-statistics.v3;
  support=the exact selected statistic.minimumSupport and supportMaps;
  availability=its support receipt closure <= immutable map history cutoff.
Do not pick the first matching generic template or select a window from a name.
Store formula template identity separately from actual dependency references.
The existing false-ambiguity guard remains useful for truly conflicting contracts.

3. DECLARED-COMPLETE IS NOT DEPENDENCY-COMPLETE

P1/S3 — ranked interactions omit the actual ranking input and current selectors.
observedDraftFeatureBundle.mjs:267-269 ranks by basis native_nw/native_gpm, then
emits nativeField * selected player's history. inputFields contains only nativeField
and history key. For a native_xpm product at a native_gpm rank, GPM is not declared.
Current hero/account/team/side selector operands are also not exact dependencies.
The basis string in formulaParameters names intent but does not supply its native
port/identity/time binding. dynamicSemanticBindings can call this authoritative.

Static counterexample (not executed): rank1 Radiant player A and B both have XPM500,
but form30(A)=0.1 and form30(B)=0.9. Initially GPM(A)=1000,GPM(B)=500 => output50;
change ONLY GPM(A)=100,GPM(B)=1000 => output450. The declared XPM/history inputs
are unchanged; the omitted sorting input explains the change. Ties use numeric
hero ID, so that selector input must be declared too. All five same-side basis
values are required to know rank1, not merely the chosen hero's value.

Implement explicit rankingBasis input and full ranking roster, selected hero
identity, selected account/team IDs for the chosen historical population, side
orientation and exact selected statistic. Golden semantic dependency checks must
vary a non-value ranking input and demonstrate it is present in the dependency
closure. Adding metadata must preserve original numeric arithmetic and name order.

P1/S4 — coherent economic-rank minute products omit current clock.
coherentEconomyContextFeatures.mjs:104-105 multiplies by minute in at(), but the
descriptor inputFields lists only native metric and heroId. Unlike team/hero
minute products at100/111, line105 omits providerGameClockSeconds. Example with
top NW1000: clock600 -> 10,000; clock1200 -> 20,000 with listed inputs fixed.
Declare same-frame providerGameClockSeconds explicitly for that variant, with
seconds-to-minutes conversion. This affects 3 metrics * 5 ranks * 3 orientations
* 4 terms = 180 declared-complete columns per LIVE head.

P1/S5 — history selector presence is requested but not bound transitively.
dynamicSemanticBindings.mjs:25 writes requiresExactSelectorBinding:true but only
stores key/definition/units/support/window; input binding says 'bound account/hero/
team selector' without the actual typed selector. Hero direct/history inputs at
observedDraftFeatureBundle.mjs:246-249 omit the current hero/account/side/team ports
that select and orient values. A shared context protects current execution, but
metadata is not yet a standalone executable dependency contract for future model
or dataset compatibility. Specify selectors in the function grammar; place actual
current IDs and source receipts in row/instance identity. Do not hash them into
the reusable function type, and do not remove them from row provenance.

P2/S6 — native-level historical reference has no producer.
observedDraftFeatureBundle.mjs:30,256-259 emits native_level hero-minute residual/z
for 250 heroes (500 columns). historyCalculationCore.mjs:12,186-193 creates only
native_nw/native_gpm/native_xpm references. Therefore selected hero level references
cannot be populated by the current canonical producer, although their descriptors
are structurally complete. This is an implementation gap, not proof Steam lacks
level. The source has literal level already. Define/add an explicit native_level
prior-frame reference path under the same exact-clock/as-of proof contract, or
record its implementation gap until the path is implemented. Do not reuse XPM as
level. Native_gold references also lack a producer, but remain opaque under S1.

P2/S7 — generic historyDefinitions is not one executable reference type.
historicalSemanticBindings.mjs:38,43 stores generic statistic formula IDs for older
profile rows; newer reviewed summary helpers store actual emitted column names.
Both currently satisfy array-of-string validation. registry-contract.mjs:132-145
validates structural fields and self-reported verification; it does not prove
executable dependency closure or exact selector consumption. Retain the historical
receipt truth ('declaration audit passed'), but stop presenting its 881,390 count
as mathematically certified features. It was explicitly not an acceptance claim.

4. DECISION S8 — TYPED DEPENDENCIES AND TRANSITIVE ELIGIBILITY

Use three disjoint reference kinds:
  input: exact source/profile/field/selector grammar, units and timestamp contract;
  feature: existing emitted definition by component namespace plus stable ID;
  formulaTemplate: reusable operator/version/parameters, never a substitute for
    an operand edge. A historical statistic reference also binds profileKind/key,
    window, support and selector grammar; it resolves to a typed input or feature.

A finite compiled DAG must prove unique resolution, no cycles, complete operators,
compatible dimensions, phase/time applicability and explicit current identity
selectors. Bind it at the SAME numerical template. Do not parse feature-name text
to invent units, source fields, time horizons or a population. Qualified provider
input has separate evidence/version binding; a copied descriptor never mints
source/causal authority. Every transform inherits the weakest source/availability
eligibility among its required operands. Missing times or unknown measurement
meaning cannot disappear through a product, aggregation, mask or formula alias.

Separate dispositions: formula specified; implementation implemented/missing;
source meaning qualified/opaque; measurement present/missing; causal available/
unavailable; source coverage measured/unmeasured; phase allowed/forbidden;
model eligibility (derived). 'Known unpicked' structural zero has its own case.
Projection inclusion uses these statuses; preserve full inventory and diagnostics.
No requirement that every conceivable unavailable feature become non-null before
the rest can be assessed. No fit is authorized by this review.
