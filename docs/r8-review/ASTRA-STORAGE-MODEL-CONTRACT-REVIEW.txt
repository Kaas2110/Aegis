1. Confirmed missing relation: separately owned schema and vector can be cross-paired
Files:
 scripts/steam-live-collector/source-adapter/featureProjectionCompiler.mjs:13-22,
 117-132; diagnosticModelInputDelivery.mjs:17-28,45-58;
 compactFeatureJournal.mjs:204-215,218-237.

The compiler authenticates a schema by exact schema hash. Its private vector record
authenticates only ordered names and count. The vector descriptor at compiler130
does not retain its originating schema/context/row binding. Input delivery.borrow
retains those two authorities independently, then describe() honestly hashes their
combined content. Therefore an accidentally assembled pair consisting of schema A
and a genuine private vector B with the same names/count is not rejected solely
because B came from another context or differently defined columns. A new manifest
created for this pair also passes the exact-manifest comparison: that comparison
authenticates the same incorrect composition, rather than its origin.

Static counterexample to implement as a small regression: generate two valid private
routes with identical column names/count but different teams/hero selectors or units
and values; call manifestFor with A.schema/A.expectedHash and B.vector; deliver the
result. The current borrow predicate accepts both private objects. Existing test
diagnosticModelInputDelivery.r7.test.mjs:19 checks tampered manifest fields and cloned
JSON, not two genuine but unrelated private objects. This is a source-derived
counterexample, not an executed failing test or evidence of a public wrong forecast.
The input port is disabled and explicitly not source-availability authority today.

Required architecture:
 A. Mint one opaque projection/row capability when the actual producer assembles a
 validated context and compiler projects it. It binds source context, causal-history
 context, map/series/side orientation, decision/receipt horizon, component row IDs,
 ordered vector identity and the set of exact authorized target-schema projections.
 B. Journal append and model input delivery consume that capability. Do not allow
 callers to create the relation by combining independently valid objects or by
 supplying JSON hashes. Separate schema/vector borrowing can remain an internal
 memory-management primitive; it is not the semantic assembly authority.
 C. Legitimate same-row multihead reuse remains: one vector may serve winner/kills/
 duration heads only when that original projected row explicitly authorizes their
 schemas. Do not disable this optimization by binding a row to exactly one target.
 D. A stable function-contract hash, described next, does not replace row capability.
 Two rows of the same model schema are still different observations. A later saved
 reader may reconstruct an equivalent verified row envelope from pinned bytes and
 source proof, but parsed JSON alone may not mint its private authority.
 E. Current diagnostic-only compiler fixtures can keep an explicit compiler-only
 forensic profile; no source-bound or inference claim follows from it. Make the
 production-required envelope distinction explicit rather than silently broadening
 the old input-only receipt.

Acceptance: cross-context private objects, changed units/formula with identical
names, swapped targets/sides, stale corrected source, expired/released capability
and cloned capability all refuse; same actual row across authorized heads succeeds.
Cover error paths before/after awaited persistence and delayed recording, with
zero leaked leases. Small synthetic regressions first; no model needed.

Required versioned identities (do not silently reinterpret existing v1/v2 hashes):
 1. FeatureFunctionContract: ordered definition IDs; exact formula/operator/version,
 input ports and selector grammar, sides/slot ordering, dtype/units/missing policies,
 history windows/support, time/as-of rules, phase/profile eligibility, patch rules,
 dependency types and registry/projection rules. Actual team IDs and actual cutoff
 instants are bindings to these functions, not separate feature functions.
 2. Transformer/model-state binding: exact fitted state/cohort/fold and approved
 producer implementation/source inventory. A code or formula change is never
 authorized merely because names match. A migration/equivalence decision is explicit.
 Causal rolling ratings are evaluated historical state and retain their past-data

 3. RowInstanceProvenance: actual series/map/roster/hero/side selectors; source raw
 hashes/profile/epoch; confirmed source time, observed receipts and decision time;
 history snapshot/cutoff/proof, actual selected row identities/support/knownAt and
 transformer-state reference; exact vector/mask hashes and authorized projections.
 4. Preserve the current exact diagnostic descriptor/hash as legacy forensic evidence.
 New storage may store the function contract once plus bounded row bindings, with
 an explicit independently checked reconstruction/equivalence path for old metadata.

Do not globally delete selector or formulaParameters fields. Each parameter needs
classification: a window of30days is a function constant, selected team100 is row
binding, and role-inference method/version is a function rule whose resulting
current assignment is row evidence. References must be typed: emitted-feature ID,
source-statistic definition ID, raw input port and learned-state reference cannot
all masquerade as historyDefinitions strings.

Acceptance matrix: same functions with different teams/heroes/cutoffs => same new
function contract, different row provenance; changed units/window/formula/source
meaning/missing policy/selector grammar => different contract or explicit denied
compatibility. Exact source correction changes row authority even if values match.
Replay from actual pinned dependencies must match online values/masks and binding.

3. Dataset architecture before any factory or fit

by target/mode, source-availability profile and stable function/state contract;
do not split map frames or connected series independently. Share that split hash

Weight equal series, then maps, then selected frames inside the actual estimator's

extra independent weights. Preserve one unit of evidence per series/component for

its state and prediction to have been available by the decision. The present plan

classification, not proven target leakage. Reject claims of original availability

Keep float64 values and explicit masks/negative-zero semantics through migration.
Float32, quantization, dimensional reduction and learned compression are later
experiments; they are not an excuse to change the present numerical contract.

6. C++ decision and cleanup
The current latency breakdown does not justify rewriting the API/server in C++.
Tree libraries already execute their numeric kernels natively. First remove repeated
schema construction/serialization/whole-root verification work under the preserved
proof contracts. Profile the complete affected operation, not an isolated arithmetic
function. If CPU dominates after that, prototype one exact kernel (canonical hashing/
compact factoring or indexed historical aggregation), using the existing failed-linker
receipt as historical evidence. Do one bounded tooling availability check only if
needed; no repeated installer searches or unscheduled purchases/installations.

Adopt a native path only with identical values/masks/order/hashes and failure behavior,
correct cancellation/ownership, fixed resource caps, and >=30% complete-operation
gain in at least three measured pairs after a separate warmup. No usable toolchain
or <30%gain => retain current implementation and record evidence; no invented speedup.
Do not rewrite network IO/API boundaries merely because they can be written in C++.

The only reported source cleanup, dangling scripts/package.json hello alias removal,
is narrow and appropriate. Absence of direct callers is not sufficient to delete
old model readers, scheduled/CLI entrypoints, format migrations or manual exports.
Continue a deletion manifest with positive replacement/import/entrypoint evidence;
deleting features or weights is outside this review and current authorization.

Final conclusion
R7 establishes useful diagnostic plumbing and clearer finite ownership, but the
next block must bind the right row to the right semantics and use stable model
function identity before scaling datasets. The highest-value acceleration comes
from sharing invariant contracts and reducing repeated IO while preserving causal
proof and durable publication. No model quality or training permission is inferred.
